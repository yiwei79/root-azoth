## Model Challenge

Use two related but different models:

- **3-tier product flow:** `root-azoth` -> public `azoth` -> installed consumer
  deployment. This remains the release/update supply chain.
- **4-plane operating model:** `root-azoth`, public `azoth`,
  `yiwei-azoth-cockpit`, and controlled consumer-project repos. This is the
  actual authority model for daily use.

The fourth plane should be named **controlled consumer-project repos**, not
generic downstream adopters. It exists because project repos own project-local
context, gates, memory, instructions/guidance, source code, and write authority.
The cockpit may route and hold pointer metadata, but it must not import project
source or treat cockpit approval as project-write approval.
