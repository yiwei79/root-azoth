# Azoth v0.3.0-rc.1 — Personal Harness OS preview

`v0.3.0-rc.1` is a prerelease candidate that introduces the portable core of
Personal Harness OS: a route-aware, minimum-sufficient path for governed
AI-assisted delivery.

The candidate is curated from the selected June 2026 Personal Harness snapshot
and subsequent publication hardening. The executable candidate validated for
this evidence record is root revision
`26d24e9e34691b9b2d6bc51e5fd18c122f5b6929`. Each extraction records the exact
release-bearing root revision in the public `azoth.yaml` manifest. The candidate
does not publish private operator state, workshop history, or
environment-specific integrations.

## Highlights

- **Effect-aware routing.** `HarnessRequest` and
  `classify_harness_request` produce a `HarnessDecision` whose `profile` field
  selects `guide`, `assisted`, `managed`, or `governed_autonomy` from intended
  effects and authority requirements.
- **Explicit transition state.** `RouteCapsule` exposes the selected route,
  required inputs, authority, next safe action, and stop reason as a
  deterministic packet.
- **Compact progressive context.** `build_context_view` joins bounded summaries
  and source pointers into a context-view packet while filtering raw memory and
  preserving advisory authority.
- **Read-only context assembly.** `build_personal_harness_context` combines
  routing, bounded recall, optional approved context, and project readback
  without granting write authority.
- **Portable behavioural rehearsal.** A generic runner evaluates
  `examples/personal-harness/rehearsal-cases.yaml`, reports route and authority
  outcomes, and verifies that representative cases do not mutate the target
  repository. The release does not lock a final CLI command name.
- **Public proof and rationale.** New documentation explains the design and the
  production lessons behind it:
  - [`docs/PERSONAL_HARNESS_OS.md`](../docs/PERSONAL_HARNESS_OS.md)
  - [*Narrow Success, Broad Failure*](../docs/case-studies/narrow-success-broad-failure.md)
- **Focused public tests.** The release candidate includes deterministic tests
  for routing, authority stops, context selection, raw-memory filtering, and
  optional-source behaviour.

## Design direction

This release treats agents as programmable probabilistic components inside a
larger engineered system. The surrounding harness defines context, deterministic
tools, authority, evidence, evaluation, stopping, and recovery.

The default is the smallest path that preserves the controls the task actually
needs. Retrieval, durable memory, richer orchestration, and multi-agent
coordination remain available when a demonstrated failure mode justifies their
operating cost.

## Product-boundary hardening

The candidate:

- generates the public manifest as `azoth`, not as the private workshop;
- preserves the existing PolyForm Noncommercial 1.0.0 licence;
- excludes machine-specific paths, private repository names, project
  identifiers, workshop counters, and private release state from the product
  tree;
- keeps private cockpit, daily-flow, campaign, memory, and operator adapters out
  of the public package;
- generates README and public CI from root-owned templates to avoid
  public/source drift;
- ships the selected portable tests in the public CI definition; and
- includes the generic rehearsal runner, consumer-facing cases at
  `examples/personal-harness/rehearsal-cases.yaml`, and a focused no-write
  rehearsal test in the public CI definition.

## Known limitations

- This is a release candidate, not the next stable Azoth release.
- Personal Harness OS remains under active refinement.
- The public package exposes the portable routing/context core, not private
  operator integrations or every workshop capability.
- No external adoption, production deployment of Azoth, package-manager
  distribution, or identical enforcement across AI hosts is claimed.
- Role-based agents, RAG, memory, and multi-agent graphs are not deprecated;
  they remain conditional architectural choices.
- Native compaction and file discovery do not eliminate the need for durable
  memory, retrieval, permissions, or semantic integrity in applications that
  require them.

## Review and publication gates

Publication requires review of the complete extracted tree, a clean public
worktree, passing validation, and explicit human approval for the exact public
commit, annotated tag, push, and GitHub prerelease.

Existing stable tags remain immutable. In particular, `v0.2.0` must not be
retargeted.
