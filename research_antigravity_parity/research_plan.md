# Antigravity Parity Research Plan

Main question: Can Azoth achieve practical parity with Antigravity as a compatible platform in the same way it currently targets Claude Code behavior and functionality?

Subtopics:

- Product identity and official surfaces: identify the exact Antigravity product/runtime and locate its first-party docs or source-of-truth materials.
- Capability mapping: verify instruction loading, prompt or command surfaces, skills or extension loading, subagent or task isolation, hook or tool interception, memory and session handoff, and local filesystem behavior.
- Parity synthesis: compare Antigravity's confirmed surfaces against Azoth's current Claude Code assumptions and classify each dimension as confirmed parity, partial parity, no parity, or unknown.

Expected outputs:

- A compact findings file for product identity and source links.
- A capability matrix showing confirmed, partial, missing, and unknown behavior.
- A final compatibility assessment with recommended adapter shape or explicit no-go reasons.

Synthesis approach:

- Prefer first-party documentation and runtime artifacts.
- Use only a small number of focused searches.
- Treat unsupported or undocumented features as unknown until confirmed.
